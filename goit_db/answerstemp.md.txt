## 1.2. Вибір інструментів

**1. Pinecone, Qdrant і Chroma.**  
Pinecone — це managed cloud-сервіс для векторного пошуку, тому його зручно використовувати в production, коли не хочеться налаштовувати власну інфраструктуру. Qdrant — open-source рішення, яке можна запускати самостійно або через Qdrant Cloud; його варто обрати, коли потрібен контроль над даними та розгортанням. Chroma — простий open-source інструмент, зручний для локальної розробки, RAG-прототипів і навчальних проєктів. Для швидкого production я б обрав Pinecone, для self-hosted production — Qdrant, для MVP або лабораторної роботи — Chroma.

**2. Чому specter2_base, а не all-MiniLM-L6-v2.**  
Модель `allenai/specter2_base` обрана тому, що вона спеціально навчена для роботи з науковими текстами. У картці моделі HuggingFace зазначено, що SPECTER2 призначена для створення ембеддингів наукових документів і використання в scientific downstream tasks, зокрема для пошуку та порівняння статей за `title` і `abstract`. `all-MiniLM-L6-v2` є універсальною моделлю, але вона не спеціалізована саме на наукових публікаціях, тому для arXiv-статей `specter2_base` є більш доречним вибором.

**3. Рекомендована метрика схожості.**  
Для таких ембеддингів доцільно використовувати `cosine` similarity, особливо якщо в коді вказано `normalize_embeddings=True`. Це важливо, бо метрика індексу в Pinecone має відповідати способу порівняння векторів. Якщо обрати неправильну метрику, пошук схожих статей може давати гірші результати. Тому при створенні індексу `arxiv-papers` варто задати `metric="cosine"`.

## 1.3. 
Косинусна схожість рахується за формулою:

cosine(a, b) = (a · b) / (||a|| * ||b||)

Якщо ембеддинги нормалізовані, їхня довжина дорівнює 1:

||a|| = 1, ||b|| = 1

Тому формула спрощується:

cosine(a, b) = (a · b) / (1 * 1) = a · b

Отже, для нормалізованих ембеддингів cosine similarity еквівалентна dot product, бо обидві метрики дають однакове значення.
